Мы отходим от примитивной схемы "агент делает, критик ругает, агент переделывает". В такой схеме агент каждый раз работает с чистого листа и не знает как выглядит хороший результат — он только знает правила чего нельзя.

Из PaperBanana (https://github.com/dwzhu-pku/PaperBanana) берём  идеи:

1. Обучение на примерах в промпте. У них 200 реальных диаграмм из научных статей — перед генерацией система подбирает 10 похожих по теме и показывает агенту вместе с исходным текстом и готовой картинкой. Мы делаем то же: собираем reference set готовых requirements документов, скрипт подбирает 2-3 по домену и подсовывает в промпт. Агент видит как выглядит хороший результат для fintech или там healthcare.

2. Veto rules — дешёвые проверки до вызова критика. Нет ссылок на источники? Regex в Python ловит это , незачем тратить вызов агента.

3. Двухуровневая иерархия критериев. Traceability и покрытие источников — tier 1, без них всё остальное бессмысленно. Acceptance criteria и полнота секций — tier 2. Критик сначала проверяет первый уровень и если он не пройден — не тратит время на второй.

Из meta_skill (https://github.com/Dicklesworthstone/meta_skill) берём идею обучения на собственных прогонах:

4. Сбор логов для адаптации. Каждый прогон пайплайна пишет JSON: вердикты критика по каждой проверке, количество ревизий, какие замечания привели к реальным правкам а какие нет. Со временем система понимает какие проверки полезны для какого домена — meta_skill решает это через Thompson Sampling (бандит с Beta-распределением на каждую проверку). На первом этапе просто копим данные.

5. Anti-pattern mining. Скрипт анализирует историю ревизий и собирает типичные причины отклонений. Если критик пять раз подряд отклоняет за одно и то же — это паттерн, его можно добавить в промпт аналитику как anti-example. Агент видит не только хорошие примеры из reference set, но и типичные ошибки из прошлых прогонов.

Из HyperAgents (https://huggingface.co/papers/2603.19461) берём идею что система должна помнить свой опыт и менять поведение на основе результатов. В их экспериментах агент-ревьюер научных статей стартовал с простого промпта и за 100 итераций сам придумал себе двухстадийную оценку с чеклистами, persistent memory с инсайтами между прогонами и детекцию собственных дегенеративных паттернов (когда скатился в 99% acceptance rate — автоматически заметил и скорректировал). Всё это не было запрограммировано — система изобрела это сама через эволюционный поиск.

берём конкретные паттерны которые они открыли: persistent memory между прогонами (как вариант — через MemPalace https://github.com/milla-jovovich/mempalace), bias detection, бюджет ревизий. Но главная идея HyperAgents в другом — агенты сами себя переписывают. Task agent и meta agent это единая редактируемая программа. Meta agent смотрит на результаты прошлых прогонов и меняет код task agent'а — добавляет чеклисты, меняет логику оценки, вводит новые проверки. А потом меняет и свой собственный код — то есть улучшает сам механизм улучшения. У нас агенты это .agent.md файлы + Python-скрипт. можно сделать то же самое: мета-агент анализирует логи прогонов, видит что критик пропускает слабые требования или аналитик игнорирует определённые замечания — и переписывает .agent.md файлы, меняет критерии проверок в скрипте, добавляет новые veto rules. Не человек правит агентов после каждого неудачного прогона, а система сама адаптируется. Агенты эволюционируют сами по себе
